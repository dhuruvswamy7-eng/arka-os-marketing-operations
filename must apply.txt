# ARKA OS — PRODUCT & TECHNICAL IMPLEMENTATION SPECIFICATION

## 1. PROJECT NAME

**ARKA OS**

### Product Type

Internal Company Management & Work Tracking Platform.

### Primary Purpose

ARKA OS is an internal system used by the Founder, Managers and Team Members to manage:

* Employees
* Teams
* Tasks
* Work progress
* Attendance
* Login/logout
* Breaks
* Lunch
* Task time
* Leave
* Reports
* Company-level visibility

The objective is to replace fragmented/manual tracking with one centralized system.

---

# 2. WHAT PROBLEM DOES ARKA OS SOLVE?

Currently, company work can become difficult to track because information is distributed across different tools and conversations.

ARKA OS should provide one centralized system where the company can answer:

> Who is working?

> Who is online?

> When did they log in?

> When did they log out?

> Who is on break?

> Who is at lunch?

> What work is assigned?

> Who is responsible for the work?

> What is the current status?

> How much task time was recorded?

> Which tasks are overdue?

> Which employees belong to which Manager?

> What is happening across the organization?

The system should provide this information in real time.

# 14. DAILY BREAK POLICY

Default company policy:

```text
Morning Break: 15 minutes

Lunch: 60 minutes

Evening Break: 15 minutes
```

However, ARKA OS should record **actual usage**.

Example:

Configured:

```text
15 + 60 + 15
= 90 minutes
```

Actual:

```text
14 + 56 + 17
= 87 minutes
```

System records:

**87 minutes actual break/lunch time.**

Do not automatically deduct 90 minutes.

# 18. LOGIN TRACKING

When employee logs in:

```text
login_at = current timestamp
last_active_at = current timestamp
status = working
```

When employee logs out:

```text
logout_at = current timestamp
status = completed
```

Every session must be stored separately.

Example:

```text
Session 1
09:00 → 13:00

Session 2
14:00 → 18:00
```

Both must remain in the database.

---

# 19. BROWSER ABANDONMENT

Do NOT fake logout if the employee simply closes the browser.

Use:

```text
last_active_at
```

and heartbeat updates.

If the employee disappears unexpectedly:

```text
status = stale/offline
```

after a defined threshold.

Do not invent a fake logout timestamp.

## Final recommendation to the developer

**Build this as a production internal company system, not as a prototype.**

The existing ARKA OS frontend is the starting point. The developer's job is to **connect the existing UI to Supabase and make every important feature actually work**.

The final infrastructure is:

**VS Code → GitHub → Hostinger → `os.arka.com`**

and:

**ARKA OS → Supabase PostgreSQL + Auth + RLS + Realtime + Storage/Edge Functions where required.**

The key attendance model is:

**ONE LOGIN → WORK → BREAK/LUNCH → RESUME → WORK → LOGOUT**

with default policy:

**15 min morning break + 60 min lunch + 15 min evening break**, while recording the **actual** duration rather than automatically deducting the configured allowance.
